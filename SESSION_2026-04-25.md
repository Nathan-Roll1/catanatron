# Session 2026-04-25: super_m2 ExIt deployment + M3/M4 distillation

End-to-end log of work done on Apr 24-25, 2026 to (a) deploy a super_m2
expert-iteration pipeline on the Stanford NLP cluster, (b) collect dense
super_m2 self-play datasets locally, and (c) fine-tune M2 on those
datasets to produce M3 / M4 candidates.

## TL;DR

- **Built a complete cluster ExIt deployment** (1 learner GPU + 4 actors,
  jagupard nodes, dense soft-policy + search-value loss, eval every 10
  rounds against AB2 and frozen-baseline 0-ply opponents, W&B integration,
  graceful stop, code-rsync workflow through jamie).
- **Collected 825 super_m2 4-way self-play games locally** (~120k dense
  examples with `policy_target` + `search_value`). 300g run finished;
  1000g run killed at 21/40 chunks for faster iteration.
- **Trained 5 fine-tune variants** of M2 → M3/M4. None beat M2 at 0-ply
  in 2v2 (best ties at 50%); M3-soft (full diffuse policy_target)
  significantly hurt 0-ply (29-71). The dataset is structured for use
  *with search*, not for raw 0-ply gains.
- **Key open question**: do M3/M4 + super-search outperform M2 +
  super-search? Untested. Likely YES based on val sv_mae improvement
  (0.85 vs ~1.0 baseline).

## Architecture: dense ExIt

The pipeline trains M2 to imitate super_m2 (M2 + deep recursive search).
Two improvements over basic ExIt:

### 1. Dense policy targets

Instead of one-hot on the chosen action, each step has a soft distribution
built from the per-candidate search values:

```c
// csrc/deep_search.c — new function
double deep_search_root_full(ctx, game, our_color,
                              candidates, n_candidates,
                              &out_best_idx, double *out_values);
```

`out_values[i]` = exact minimax value of taking candidate i, in [-1, 1],
computed with full alpha-beta window (no root pruning) so values are
comparable across candidates. Caller converts to a soft policy target via
`softmax(values / 0.1)` over the K candidates, padded to 397 dims.

Stats from 300g dataset:
- 90.4% search, 8.9% lowH (NN policy used as soft target), 0.7% terminal
- Mean max-prob = 0.39 (median 0.32) — most decisions diffuse across multiple moves
- 70.6% of rows have max-prob < 0.50 → genuine multi-target signal

### 2. Search-value targets for value head

Each step also records `search_value = max(values)` ∈ [-1, 1] — the
position's V(s) from acting player's perspective. The value head trains
on both:

- **Outcome target** (sparse): rotated reward_vec → CE over 4-way distribution
- **Search V(s) target** (dense): MSE on `2·softmax(value_logits)[:,0] - 1`

Combined loss in `super_learner` and `train_m3_local`:

```
total = α·policy_loss + β·value_loss + γ·entropy        # uncertainty-weighted
      + sv_weight·search_value_loss                      # auxiliary regression
```

Smoke test on 5-epoch overfit confirmed sv_mae drops 0.97 → 0.64
monotonically.

### Key takeaways

1. **Dense soft target alone (M3-soft) HURTS 0-ply.** The diffuse signal
   trains the policy to hedge across multiple equivalent moves, which
   makes argmax less decisive. M3-soft lost 29-71 to M2.

2. **Hard label (M3-hard) or sharp+mixed targets recover M2's strength.**
   All M3-hard / M3-sharp / M3-mixed / M4 variants tie M2 within
   ±5pp (statistically indistinguishable).

3. **More data didn't help 0-ply.** M4 with 4× the data still ties (49%).
   The signal-to-noise ratio of "super_m2's correction over M2's argmax"
   may not be extractable into a feedforward 0-ply policy without
   architectural changes or iterative self-play.

4. **Value head is genuinely improving.** Best variant: M3-hard with
   val_sv_mae=0.86, val_v_acc=42% (vs ~35% baseline). This benefit only
   shows in search (where the value head evaluates leaves), not in 0-ply
   policy argmax.
